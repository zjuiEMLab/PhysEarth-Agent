Section 03The six phases

Each phase is one commit on a branch, moved with git mv so blame survives, and ends with the full suite passing and the Studio launching. Rollback is always git revert of a single commit.

Phase 2

Split the four oversized modules, in place

1.5 d

Each becomes a package whose __init__.py re-exports every public name, so no import anywhere else in the repository changes. This is the highest-value, lowest-risk phase, and it is worth doing even if you stop here.

physearth/research.py  3,894 → research/{plan,repair,review,coverage,protocol}.py
physearth/tools.py     2,579 → tools/{literature,models,charts,data,registration}.py
physearth/agent.py     1,770 → agent/{loop,stream,messages,faults}.py + __main__.py
physearth/ui/render.py 1,881 → ui/views/{answer,trace,evidence,charts,review,registration}.py

agent/__main__.py is new, not a move: it gives you python -m physearth.agent "question" --model smrt headless, which is the "standalone script" requirement and also the fastest way to reproduce a bug without the UI.

Verify

pytest tests -q green with zero import edits outside the four split directories — git diff --stat proves it. Plus python -m physearth.agent --help.

Then collapse the coupling. ui/render.py currently imports 8 backend modules (agent, approval, budget, knowledge, live, models, reference, research), three of them lazily inside functions; studio.py calls roughly 25 backend functions. All of it goes through one new backend/physearth/api.py.

The two invariants, as tests: no file under backend/ may import gradio; no file under frontend/ may import physearth.research, physearth.tools or physearth.agent directly. Three lines each, and they are what stops the split eroding.

Verify

pytest tests -q; the two new invariant tests; python app.py serves and renders. test_ui.py needs its assets/ and app.py paths updated — 6 call sites.

Phase 4

Two jobs beyond the move. One: backend/physearth/paths.py replaces the three hard-coded Path(__file__).resolve().parent.parent / "knowledge" constants in knowledge.py, reference.py and model_guidelines.py. Those fail silently — an empty corpus, no exception — so they must resolve through one function that works from a checkout and from an installed wheel. Two: delete the 20 sys.path.insert calls across evaluation/ and tests/, which become unnecessary once the package is installed with uv sync.

Verify

uv build, then in a clean venv: pip install dist/*.whl && python -c "import physearth; physearth.paths.knowledge()" and confirm the corpus is non-empty. Plus python evaluation/runners/tier0.py reproducing its committed JSON. Do not accept a passing pytest as proof here — the checkout masks a broken wheel.

Phase 5

Extract prompts into levels

1.0 d

The mapping is in Section 04. prompts.py keeps build(state)'s current assembly order and switch behaviour exactly; only the text moves out to files.

Do this before deleting anything: capture prompt.build(state) output for every combination of the three switches (literature, capability, online on/off) as fixtures, then assert the new assembler reproduces them byte for byte. A prompt reorganisation that quietly becomes a behaviour change would invalidate every committed evaluation record in evaluation/results/.

Verify

The byte-identical fixture test, then pytest tests/test_switches.py tests/test_evals.py -q, then one live agent run compared against a cached record.

Phase 6

Consolidate models/ and evaluation/

1.0 d

Sections 05 and 06. The registry mechanism moves to backend/physearth/registry/; the cards, template and examples come to top-level models/. In evaluation/, the two taxonomies merge and a single run.py replaces 12 separately-invoked runners.

Verify

python evaluation/run.py tier0 and python evaluation/run.py registration must reproduce evaluation/results/tier0.json and model_registration.json byte-identically — these are deterministic and need no LLM, so any drift is a real defect. Then rebuild the wheel and confirm registry still finds all six bundled models from an installed wheel.

Section 09Explicitly not in scope

  • No behaviour change: no physics, prompt wording, tool contract or UI copy is edited. Only locations and module boundaries.
  • No dependency changes beyond syncing the venv to the existing lockfile.
  • No package split — that is Option D, and Section 07 only keeps the door open.
  • evaluation/results/ is evidence; nothing in it is regenerated or deleted.
  • The failing figure test is not fixed by this plan; it is fixed by uv sync in pre-flight. If it still fails afterwards, that is a real defect and a separate task.

Sequence to start: pre-flight (uv sync --extra dev, record a green baseline) → Phase 1 → Phase 2. Those three are safe, independently valuable, and reversible with a single git revert each. Phases 3–6 want the models/ packaging decision in Section 05 answered first.
