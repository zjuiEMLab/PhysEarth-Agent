01 — The prior question

Has the repository earned D yet?

A four-package monorepo is not a tidiness upgrade. It is a coordination cost accepted in exchange for independent release. Six conditions normally justify that trade; here they are, scored against the tree as it stands today.

Not met

More than one deployable

Still one Gradio Studio, and the README front-matter still pins entry_file: app.py. backend/physearth/agent/__main__.py exists, so headless runs already work — but it ships no console script and is not released separately. A module you can invoke is not a second deployable.

Partial

Third parties install one piece without the rest

Unchanged as an ambition: breadth is meant to come from the registration mechanism. If someone should pip install physearth-models and register against the contract without pulling Gradio, that is the one argument for splitting with real force. It argues for a second package, not a fourth.

Not met

Separate release cadences or separate teams

One maintainer, one cadence, and no release process to speak of. Cross-package version pinning would be ceremony performed for an audience of one.

Partial

Irreconcilable dependency conflicts

The strongest technical signal, and it has not improved. models/bundled/smrt/adapter.py still assigns sys.modules["numba"] = None around its import, and .gitignore still carries .venv-pws/. Models are straining against a shared process — but the fix is per-model environments or subprocess isolation, which is a runtime decision, not a repository layout.

Not met

Build or CI time is painful

The suite runs in about 45 seconds. More pointedly, there is no CI at all — no .github/workflows — so there is no build time to be painful. Nothing to parallelise.

Partial

Licence or redistribution boundary

124 files under knowledge/ are CC-BY literature redistributed under per-paper attribution in a 91-line NOTICE, sitting inside an Apache-2.0 codebase. Separating data from code has a real rationale — and argues for one extra distribution, not three.

3not met
3partial
0met

The score has not moved since August. More useful than the total is where the partials point: every one of them lands on the same two seams — models-versus-agent, and data-versus-code. None of them points at physearth-eval.

The finding worth taking away

Three of D's four packages have an argument behind them. physearth-eval has none. It is not installed by third parties, has no separate cadence, carries no licence boundary, and its runners are repository tools rather than a library. Promoting it to a distribution buys a workspace dependency in every runner and returns nothing.

Two things about this tree are worth stating plainly. The first is that app.py must keep booting from the repository root exactly as it does now, because the ModelScope deployspec pins the filename — that constraint survives every reorganisation and is not negotiable.

The second is .github/workflows/. D's entire value is that package boundaries are enforced rather than merely drawn. Nothing enforces them today, because there is no CI. Adding four wheels without adding the thing that checks they still build independently produces the costs of D and none of the benefit.

03 — Before anything moves

Three blockers, all pre-existing

None of these are caused by the migration, and all of them make it unsafe to start. A reorganisation whose gate is "the suite still passes" needs a suite that passes first.

The test suite does not collect at HEAD

tests/test_evals.py:8 imports llm_robustness, model_registration, reproduction_eval from evaluation.runners. All three were removed from the tree in the last two commits, so the import fails and pytest aborts collection for the whole run. This is red on main and on origin/main.

Gate
pytest collects and passes before phase 1 begins.

55 uncommitted paths, and a stash nobody has claimed

44 modified, 3 added, 3 deleted, 5 untracked — largely the competition-judge and dashboard work. Separately, stash@{0} holds 333 insertions across evaluation/metrics/score.py, frontend/studio.py, frontend/views/evaluation.py, ui.css and tests/test_evals.py. A file-moving migration over an uncommitted tree makes every conflict ambiguous: you cannot tell your edit from the move.

Gate
working tree clean; stash reviewed and either applied or dropped deliberately.

One decoupling decision from Option C never landed

Three of the four C-era decisions did land: the facade api.py exists, paths.py exists, and models/ imports nothing from the package. The fourth did not — backend/physearth/diagnostics.py:153 still reaches into the SMRT adapter for the private _ensure_smrt_importable by getattr. Cross-package imports of underscore-private functions are precisely what makes a split fail late and confusingly.

Gate
a declared warmup() on the registry contract; no private symbol crosses the boundary.

05 — Risk

What breaks, and what catches it

Each of these has bitten this repository before, or is a documented invariant that a file move would silently void.

The boundary tests stop meaning anything

tests/test_boundaries.py enforces three invariants: nothing under backend/ imports Gradio, nothing under frontend/ imports past physearth.api, and app.py delegates to frontend.studio. All three are written against paths. Move the paths and they pass vacuously — the worst failure mode, because it is silent and looks like success.

Catch
Restate all three as package-dependency rules in phase 3, and prove each fails when deliberately violated.

The 48 prompt digests

tests/test_prompt_layers.py pins every combination of the ablation switches, the online layer and session state by sha256. prompts/ moves into the core package in phase 3, and any change to how the text is assembled — even a path change that alters nothing a reader would notice — trips all 48 at once.

Catch
Expect them green through the move. Regenerate with PHYSEARTH_UPDATE_PROMPT_FIXTURES=1 only for a change you can name.

Committed evaluation evidence gets "fixed"

evaluation/results/ is committed evidence behind REPORT.md, not build output. Re-running Tier 0 shifts values by 1e-16 to 1e-11 through BLAS round-off, so a verification run leaves tier0.json modified without anything being wrong. The temptation during a migration is to commit the drift.

Catch
The gate is the assertion — 9/9 tasks, 38 checks — never a byte-identical file. Revert the drift.

Mixed CRLF and LF line endings

Tracked .py files carry randomly interleaved CRLF and LF. Any tool that rewrites a whole file normalises them and produces an enormous spurious diff that hides the real change inside it.

Catch
git mv for moves; edit in place. Never round-trip a file through a formatter during a move phase.

The ModelScope deployspec

The README front-matter pins entry_file: app.py. A workspace layout changes what is importable from the repository root, and from the root . is on sys.path — which hides exactly the difference that breaks the deployed app.

Catch
Verify by building and importing from a clean venv in a neutral working directory, as AGENTS.md already requires for packaging changes.

Packaging does not fix the numba conflict

It is worth being explicit, because condition 4 is the strongest signal on the board and the most tempting to over-read. Splitting physearth-models into its own distribution does not stop SMRT mutating sys.modules["numba"] in a shared interpreter. Same process, same problem.

Catch
If this is the real motivation, the fix is subprocess isolation or per-model environments — buy that directly, not via a repository layout.
06 — The alternative

Where the evidence actually points

Same ladder proposed in August, with today's position marked. Each rung is a real resting place: shippable, readable, and green.

C — one distribution

physearth, with models/, prompts/, evaluation/ and knowledge/ as top-level content. Complete since August.

C+ — two or three distributions

physearth + physearth-models, and physearth-knowledge if the licence boundary is the motivation. This captures all three partial conditions. Roughly phases 0–5 of the plan above: 4.25 days, and it leaves D a rename away rather than a rewrite.

↓  only if a second deployable actually exists

D — four distributions, workspace, CI matrix

Adds physearth-eval as a distribution and an apps/ tier for surfaces that do not exist yet. 6.5 days. The remaining 2.25 days over C+ buy independent release for a package nobody installs and a deployable nobody has written.

If you want D regardless — because you are pitching the repository as production-grade, or because a second surface is genuinely coming — the plan above is complete and the phases are real. It is a defensible thing to want for reasons that are not on this scorecard. I would only ask that the reason be one of those rather than tidiness, because tidiness is what Option C already bought.

07 — Decisions

Four things only you can settle

Everything else in the plan follows from code and can be settled by reading it.

Is a second deployable actually coming?

An HTTP API, a worker, a headless CLI you intend to publish. If yes, apps/ earns its place and D is the right target. If it is hypothetical, phase 7 builds a skeleton that will rot.

Is the numba conflict the real driver?

If the motivation is that SMRT and pywatershed cannot share an environment, say so — the answer is subprocess isolation, which is cheaper than this entire plan and actually solves it.

D, or C+ first?

C+ is phases 0–5 and stops at a coherent resting point. Going straight to D is 2.25 days more with no intermediate state worth shipping.

What happens to the 55 uncommitted paths and the stash?

Phase 0 cannot start until this is settled, and it is your work — I am not going to guess which of it is wanted. The stash in particular holds 333 insertions that may or may not be superseded.
