Completed evidence

Model registration tests

The registration path asks whether a model is declared completely, rejects invalid configurations, can be discovered, and can run a minimal bundled example. These checks establish operational readiness, not scientific truth by themselves.

Registry contract

All six registered models are inspected. Every numeric minimum and maximum, enum, combination rule, and sweep contract is exercised.

Result: 6 / 6 models; 191 / 191 checks.

Deterministic adapters

Nine tasks cover upstream agreement, published values, identities, monotonic behavior, output quality, and alignment.

Result: 9 / 9 tasks; 38 checks.

Replay evidence

Successful records retain the model version, resolved specification, output arrays, check configuration, and a replay key.

Reproducible commands

Execution order

  1. Run the registry contract checks.
  2. Run the deterministic adapter checks.
  3. Run the registered-model demos.
  4. Regenerate the dashboard.
  5. Only after the registration evidence is stable, explicitly execute paper reproduction.
