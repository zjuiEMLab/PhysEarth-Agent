Evaluation proposal

From “it runs” to “the result is explainably trustworthy.”

PhysEarth-Agent is intended to support scientific work. The evaluation should therefore test the real sequence: register a physical model, reproduce a published paper, and only later attempt independent research.

Model registrationPaper reproductionProvenanceSafetyReplayability
Competition boundaryIndependent research and novel discovery are not evaluated in the current competition. A successful adapter test must not be presented as proof that an Agent has reproduced a paper.
Evidence boundary

What the evaluation can and cannot claim

Strong evidence

Registered model cards, deterministic adapters, domain validation, and replayable traces are directly testable.

Intermediate evidence

Paper parameter extraction can be tested field by field, including source spans and explicit assumptions.

Insufficient by itself

Completion rate alone does not demonstrate scientific reproduction. A result needs legal execution, provenance, comparison, and review.

Evaluation area one

Model registration tests

This area asks whether a new or existing physical model is represented consistently enough to be discovered, validated, called, and replayed.

Model-card contract

  • Name, version, license, citation, entrypoint.
  • Units, defaults, required fields, numeric domains.
  • Enums, legal combinations, sweep behavior, output schema.

Adapter truth

  • Upstream package agreement where available.
  • Published values and closed-form identities.
  • Boundary behavior, monotonicity, finite outputs, and ranges.

Trace integrity

  • Resolved parameters and model version.
  • Complete output arrays and check configuration.
  • Replay key, refusal reason, and approval state where relevant.

The current implementation covers six registered models and nine deterministic adapter tasks. It makes no language-model calls.

Evaluation area two

Paper reproduction results

SMRT is the current paper target. The evaluation must test the full research workflow instead of only checking whether a few parameter values look plausible.

Evidence gateQuestionFailure meaning
Source extractionCan the Agent locate the stated model, parameters, units, conditions, and figure target?The paper configuration is not yet identifiable.
Research planDoes the plan state objective, baseline, controls, diagnostics, success criteria, and stop conditions?The run is not a controlled scientific comparison.
Legal executionDoes the Agent use approved planned runs and reject invalid configurations?The output cannot be treated as a valid reproduction.
ComparisonDoes the result agree with the paper or an independent reference under the stated uncertainty?The result is partial, failed, or not identifiable.
ProvenanceAre paper facts, user inputs, derivations, defaults, assumptions, and unknowns separated?The result has a trust failure even if the number looks close.
Cross-cutting factor

Research-plan methodology

The prompt method is an experimental condition. It should be changed while keeping the paper, task, model, source access, approval policy, and scoring rules fixed.

ProfileMethodWhat it tests
Explore–Refine–ProduceBroad exploration, structured refinement, then execution.Baseline research workflow.
Reproduction-firstRecover source-stated facts and configuration before proposing extensions.Resistance to premature invention.
Uncertainty-awareExpose unknown fields, alternatives, assumptions, and stop conditions.Trust calibration under incomplete papers.
Future profilesFalsification, empirical, and pragmatic variants.Broader methodological comparison after the competition.
Interpretation ruleA prompt profile should not be declared better because it completes more runs. Compare reproduction validity, safety, provenance quality, human correction burden, and cost together.
Trust and uncertainty

Make facts and guesses distinguishable

Field-level labels

Every graded parameter should identify its source kind, source reference, source span when applicable, and value status.

Hard provenance gate

A numerically correct value with a fabricated paper attribution is a trust failure, not a full success.

Outcome vocabulary

Use reproduced, partial, not identifiable, and failed. Do not collapse these states into a single completion rate.

Model comparison

Separate system effects from model effects

Use the same task, prompt profile, build, approval policy, and repeat structure when comparing language models. Keep model identity, token usage, latency, and reported cost in raw records for audit, but do not let operational metadata become a scientific score.

Dashboard proposal

Show the evidence chain, not only a leaderboard

Registration view

Registered models, versions, contract checks, demo status, output summaries, and replayability.

Reproduction view

SMRT cases, execution status, outcome, comparison evidence, provenance, and limitations.

Internal analysis

Prompt × model × task summaries, token counts, cost, latency, and raw run drill-down for later experiments.

Public page ruleThe public dashboard uses plain labels that first-time users understand. Operational provider details and internal ledgers remain implementation artifacts rather than headline results.
Implementation roadmap

Stage the work without overclaiming

  1. Keep the registration tests deterministic and replayable.
  2. Use the bundled model demos to verify the user-facing path.
  3. Execute SMRT reproduction only after the registration evidence is stable.
  4. Add hidden onboarding fixtures and broader prompt methods after the competition.
  5. Only then consider independent research evaluation.
Recommended decisionPublish registration evidence now, label SMRT paper reproduction as not executed, and avoid a combined score that mixes completed deterministic checks with unfinished language-model experiments.
